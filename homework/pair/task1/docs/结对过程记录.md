## 第一次讨论：确认需求范围

两人先阅读客户描述，发现核心问题不是“缺少聊天工具”，而是信息分散、旧消息容易被覆盖、寻找信息成本高。因此确定只做校园失物招领的信息发布和查找，不加入即时聊天、地图定位、实名认证和复杂后台。

讨论后将用户分为遗失物品的学生、捡到物品的学生和普通浏览者。三类用户的共同核心操作是浏览、搜索、发布和联系发布者。

## 第二次讨论：确定页面和流程

两人把功能整理成三个底部入口：首页、发布和我的。首页负责浏览，搜索页面负责筛选，详情页面负责确认信息，发布页面负责创建信息，我的发布页面负责修改状态。

最终确定以下主要流程：

1. 首页 → 搜索 → 查看详情 → 联系发布者。
2. 首页 → 发布 → 填写信息 → 发布成功。
3. 我的发布 → 修改状态。

## 第三次讨论：原型检查

两人按“浏览详情”和“发布成功”两条流程依次检查页面。重点检查搜索入口是否明显、发布表单是否过长、详情联系方式是否容易找到、状态修改是否清楚。根据检查结果，保留统一的卡片结构，并把发布寻物和招领合并到同一页面。
