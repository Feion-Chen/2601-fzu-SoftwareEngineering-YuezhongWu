# 原型设计说明

## 一、原型工具

本次原型使用 Figma 进行整理和展示。设计素材同时保存为 SVG 文件，便于重新导入 Figma、修改文字和建立 Page 之间的交互连接。

在线原型链接：FIGMA_LINK_PLACEHOLDER

备用在线演示：prototype/index.html。该页面可以直接点击体验首页、搜索、详情、发布、发布成功和我的发布页面。

## 二、信息架构

应用包含三个底部入口：

- 首页：浏览失物与招领信息。
- 发布：发布寻物或招领信息。
- 我的：查看自己发布的信息并修改状态。

页面层级保持简单：

1. 首页 → 搜索 → 搜索结果 → 详情。
2. 首页 → 详情 → 联系发布者。
3. 首页 → 发布 → 发布成功 → 我的发布。
4. 我的发布 → 修改状态 / 查看详情。

## 三、页面设计

### 1. 首页

首页顶部显示校园名称和应用名称，搜索框固定在页面靠上位置。分类标签用于快速切换全部、寻物和招领。每条信息使用统一卡片展示物品名称、信息类型、地点、时间和简短描述。底部导航提供首页、发布和我的三个入口。

### 2. 搜索页面

搜索页面保留关键词输入框，增加类型和地点筛选。搜索结果列表只展示最必要的信息，点击任一结果即可进入详情。

### 3. 信息详情页面

详情页面展示物品图片占位、信息类型、物品名称、发布时间、类型、地点、时间、当前状态和描述。页面底部设置固定的“联系发布者”按钮，减少用户寻找操作入口的时间。

### 4. 发布页面

发布页通过顶部切换按钮区分“我丢失了物品”和“我捡到了物品”。两种类型共用同一套表单，填写物品名称、类型、地点、时间、描述、图片和联系方式。这样既减少设计复杂度，也方便第二次结对作业复用数据结构。

### 5. 发布成功页面

发布成功后显示醒目的成功提示，并展示刚发布的信息摘要。用户可以查看“我的发布”或返回首页。

### 6. 我的发布页面

该页面显示全部发布、寻找中和已归还数量。每条信息提供“修改状态”和“查看详情”操作，使用户可以在物品找到或归还后及时更新状态。

## 四、交互说明

- 首页搜索框进入搜索页面。
- 首页或搜索结果中的信息卡片进入详情页面。
- 详情页的“联系发布者”按钮打开联系方式提示。
- 首页的“发布”按钮进入发布页面。
- 发布页面提交后进入发布成功页面。
- 发布成功页面进入“我的发布”。
- “我的发布”支持在两则状态之间切换。

## 五、设计取舍

1. 不设计即时聊天，只用联系方式满足联系需求。
2. 不设计地图，地点通过文字填写和筛选完成。
3. 不做实名认证，避免增加原型流程复杂度。
4. 寻物和招领共用表单，减少页面数量。
5. 使用状态修改代替删除，保留历史信息。

## 六、后续实现建议

第二次结对作业可以优先实现登录、信息列表、发布表单、搜索、详情和状态修改。数据表至少包含用户、信息类型、物品名称、地点、时间、描述、联系方式和状态等字段。图片上传和审核可在基础流程完成后增加。
