# 陈飞扬个人总结

在本次结对作业中，我主要负责需求整理、用户分析，以及发布和“我的发布”页面的设计。通过学习《构建之法》中需求分析的相关内容，我意识到不能一开始就讨论具体代码，而要先明确用户是谁、用户真正遇到的问题是什么。客户描述中最重要的痛点是信息分散和容易过期，因此我们决定把产品定位成一个“集中发布和查找信息”的基础工具，而不是功能很多但流程复杂的聊天软件。

在与蔡以恒讨论时，我们出现过一次分歧：是否要在第一版中设计地图定位。后来考虑到作业要求、实现难度和后续结对编程的时间，我们决定只保留文字地点和地点筛选。这个取舍让我认识到，原型设计不仅是把页面画出来，还要敢于删掉与核心目标无关的功能。

我最大的收获是学会了用统一字段描述功能。例如所有寻物和招领信息都包含名称、类型、地点、时间、描述、联系方式和状态。这样原型结构更清楚，第二次结对作业也更容易把页面转换成数据模型。今后我会更重视需求边界和页面流程的检查，而不是只关注界面是否好看。

遇到的问题：最初发布页面字段太多，用户需要填写很久。后来我们把寻物和招领合并，并减少非必要字段，只保留帮助他人判断和联系物品的关键信息。
